## Notes

### Patterns Observed

1. **Authority/Signal Terminology**: "Authority," "signal," "evidence," "provenance" are used interchangeably in ADR-005 without stepping through definitions. Agents will spend 5+ minutes re-reading trying to build a mental model.

2. **Phase/Shipping Status**: Multiple docs reference ADR-005 phases without consistently stating which are shipped, planned, or deferred. Creates confusion during debugging: agent assumes Phase 2 is live when it's still planned.

3. **Passive Voice Agency Loss**: Sections like Phase 2 migration guidance use passive voice ("Build X," "Wire Y," "Add Z") without saying _which slice_, _which module_, or _which pull request_ is responsible. Agents code in wrong locations.

4. **Pronoun Ambiguity**: "The original sketch," "it," "that" used without clear referents in ADR-005 and architecture docs. Agents search for artifacts that don't exist.

5. **Dense Multi-Clause Sentences**: ARCHITECTURE.md lines 17–21, gotchas.md lines 113–120. Technically correct but require multiple passes to parse. Moderate risk; doesn't block understanding but slows down agent comprehension.

- **Low (3)**: Issues that are readability/ergonomics improvements rather than blocking clarity problems. Examples: table layout, dense but correct sentences, missing rationale for correct rules.
