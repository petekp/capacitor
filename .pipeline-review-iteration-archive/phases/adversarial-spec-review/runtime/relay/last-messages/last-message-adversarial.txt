The biggest problems I found are:
- The spec’s “preserve `decision.json` on disk after resume failure” path conflicts with its own active-milestone invariant, so the review can look recovered in memory and then disappear after restart.
- The design still trusts the worker to obey milestone numbering; wrong directories, skipped numbers, or `completion.json` written alongside a new milestone can wedge the loop or skip review entirely.
- There’s no stuck/protocol-violation state, so incomplete milestones and non-terminating workers can leave a delegation in permanent `working`.
- The standalone `Window(id: "delegation-review")` plan is missing a per-project window state model and clashes with the current main-window navigation flow.
