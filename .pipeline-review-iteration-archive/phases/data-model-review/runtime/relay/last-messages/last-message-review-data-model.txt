1. `Resume` is not milestone-validated. Swift already sends `milestone_id`, `brief_path`, and `manifest_path` when a review decision is submitted in [DelegationLoopManager.swift](/Users/petepetrash/Code/capacitor/apps/swift/Sources/Capacitor/Models/DelegationLoopManager.swift#L436), but the reducer ignores those fields on `Resume` in [mod.rs](/Users/petepetrash/Code/capacitor/core/capacitor-core/src/reduce/mod.rs#L378). In a numbered-history model, that means a stale approve or request-changes can clear or complete the wrong review once older milestones remain visible.

2. Multiple workers per project are still structurally blocked. The reducer stores delegations by `project_path` in [mod.rs](/Users/petepetrash/Code/capacitor/core/capacitor-core/src/reduce/mod.rs#L18) and rejects a second active delegation for the same project in [mod.rs](/Users/petepetrash/Code/capacitor/core/capacitor-core/src/reduce/mod.rs#L234). Swift mirrors that singleton shape in [AppState.swift](/Users/petepetrash/Code/capacitor/apps/swift/Sources/Capacitor/Models/AppState.swift#L101). Per-worker milestone numbering is fine on disk, but the system is not concurrency-ready yet.

3. Readiness detection is race-prone. Reconcile currently marks a review ready as soon as `brief.md` and `manifest.json` both exist and no `decision.json` is present in [DelegationLoopManager.swift](/Users/petepetrash/Code/capacitor/apps/swift/Sources/Capacitor/Models/DelegationLoopManager.swift#L544). Extending that to numbered milestones means a partial write or multiple undecided directories can be surfaced without any atomic “ready” handshake.
